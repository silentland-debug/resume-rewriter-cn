# 科研与机械项目的企业化转译

## 核心原则

项目名称和论文主要证明研究层级；项目经历要证明“能完成什么企业任务”。

不要把论文摘要搬进求职简历，也不要把“研究了某理论”直接改成“具备某能力”。先还原真实工程链。

## 机械/机器人项目优先还原的工程链

需求/问题 → 方案 → 结构设计 → 选型 → 建模/仿真 → 图纸/BOM（仅有证据时） → 加工/供应商对接 → 零件验收 → 装配 → 调试 → 测试验证 → 结果/交付

不要求每个项目都有完整链条，只写本人真正参与的环节。

## 结果不是只有“结题”

科研项目的求职结果可以是：
- 实体样机完成并运行
- 完成某类运动、载荷、精度或轨迹实验
- 形成工程图、BOM、程序、测试报告、实验数据
- 完成某项结构优化、加工落地或现场验证
- 对应形成论文、专利、竞赛成果
- 项目完成某阶段里程碑

“项目结题/在研”只是项目状态，不等于个人贡献。若结果缺失，先追问再写。

## 竞赛与课程设计：先挖项目，再写奖项

竞赛名称、奖项级别、课程名称本身都不是工程证据。看到与JD相关的技术竞赛或课程设计时，先问清：做了什么对象、本人负责什么、用了什么工具、形成什么交付、最终做到什么状态。

如果确认存在真实技术工作，可将其从“荣誉奖项/课程”升级为项目经历，并按工程链表达。奖项只作为结果之一。

如果只能确认“参加过/获奖”，不能确认个人技术动作，则不要自动补结构设计、建模、工程图、加工、装调或测试经历。

## 不同岗位的转译重点

### 机械设计 / 结构 / 非标自动化
优先：结构方案、三维建模、工程图、公差、选型、加工、供应商对接、装配调试、可靠性验证。

### 机械研发 / 机器人研发
优先：结构设计 + 样机 + 控制/实验 + 验证；论文可保留1—2项作为研究深度信号。

### 工艺 / 制造
优先：工艺路线、工装夹具、加工可制造性、质量问题、现场改善、标准化文件。

### 设备 / 运维
优先：设备对象、故障场景、维护标准、异常处理、停线/可靠性/安全等结果；不要只写“负责设备维护”。

### 质量
优先：检验对象、标准、问题分析、整改闭环、质量记录和结果；没有真实指标不硬造良率提升。

## 论文与学术成果

- 求职版只保留最有区分度且状态明确的成果。
- 明确作者位置、录用/发表/在投状态，仅在原材料支持时写。
- 多篇英文长标题不宜挤占主简历，可压成“SCI一区已录用1篇、EI已录用1篇”，或放作品集/个人主页。
- 不自动把论文归因到某项目；先确认是否为该项目直接成果。
