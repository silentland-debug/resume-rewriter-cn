# 工大机械类求职简历 Skill

`gongda-mechanical-resume` 是一个面向机械类学生本人直接使用的求职简历定制 Skill。

它不是把原简历“润色得更像企业语言”，而是要求先看目标岗位 JD，再回到学生的真实经历中寻找能够支撑岗位判断的证据。

## 适用对象

主要面向机械工程、机械设计制造及其自动化、机械电子、飞行器制造、智能制造等方向的学生，尤其适合实习、秋招和校招岗位定制。

典型岗位包括：

- 机械设计 / 结构设计
- 机器人研发
- 非标自动化
- 工艺 / 制造
- 设备 / 运维
- 质量

## 核心流程

**拆 JD → 对证据 → 扫描潜在线索 → 追问补证据 → 材料取舍 → 工程化改写 → HR 复审 → 一页 A4 定稿**

### 1. 拆 JD

先回答岗位实际做什么、硬门槛是什么、企业真正关心哪些工程结果，而不是先改简历。

### 2. 对证据

把 JD 要求逐项映射到原简历，区分：

- 直接证据
- 可迁移证据
- 暂无证据
- 信息冲突 / 需要确认

### 3. 扫描潜在线索

除了已经写成“项目经历”的材料，还会继续检查：

- 技术竞赛与奖项
- 课程设计、毕业设计、大作业
- 论文、专利、科研课题
- 只有名称没有动作和结果的简略项目
- 实习中一句带过、但可能包含设计、加工、装调、测试或异常处理的内容

这里的核心原则是：**名称只能作为线索，不能直接当成证据。**

例如简历中只有“全国三维数字化创新设计大赛省级一等奖”，Skill 不会直接推断学生做过 SolidWorks、工程图或装配，而会先追问：这个比赛做的是什么作品？学生本人负责哪一部分？

确认存在真实的岗位相关技术工作后，竞赛可以从“荣誉奖项”升级为“项目经历”；如果只是参赛、个人贡献不清或与岗位弱相关，则继续压缩为普通荣誉。

### 4. 追问补证据

默认一次只问一个最影响岗位判断的问题。学生只负责回忆真实事实，GPT 负责判断岗位匹配。

常见追问围绕：

- 本人具体做了什么
- 面对什么对象或问题
- 使用什么工具 / 方法
- 有没有出图、选型、加工、装配、调试、测试
- 最终交付了什么
- 项目做到什么状态

不会一开始就逼学生补数字，也不会把行业常识变成学生经历。

## 机械类工程链

机械设计 / 机器人 / 非标自动化类项目通常优先检查：

`需求 / 问题 → 方案 → 结构设计 → 选型 → 建模 / 仿真 → 图纸 / BOM（仅有证据时） → 加工 → 装配 → 调试 → 测试验证 → 工程交付`

不要求每个学生都拥有完整工程链，只写本人真实参与的部分。

## 真实性边界

Skill 不会自动新增：

- 工程图、BOM、GD&T 等未确认交付物
- 客户、供应商或量产经历
- 成本、效率、精度、良率等没有口径的数据
- “主导、全权、精通”等超出学生身份和证据范围的职责
- 团队成果对个人的错误归因

“简历没写”与“学生不会”必须区分。

## 输出

可根据学生需要输出：

- JD 拆解
- JD—证据表
- 逐步追问
- 局部项目改写
- 完整一页求职版
- A4 HTML
- DOCX / PDF 成稿

完整中文求职版默认使用 Skill 内置的 `assets/mit-template-b-cn.docx` 作为母版。

## 安装

在支持 Skills 的 ChatGPT/Codex 环境中安装 `gongda-mechanical-resume` 目录或对应的 `skill.zip`。

当前仓库中的路径：

`skills/gongda-mechanical-resume/`

## 隐私

公开仓库不应提交真实学生简历、手机号、邮箱、照片、身份证明或其他个人信息。仓库只保留工作流、规则、模板和脱敏说明。
